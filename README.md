# STOtesel — сайт автосервісу

Astro + Cloudflare Workers + Supabase. Дизайн, тексти й поведінка взяті з макета `stotesel.html`.

- Сайт: https://stotesel.stotesel.workers.dev
- Адмінка: `/admin`
- Репозиторій: https://github.com/stotesel/0
- Автодеплой: кожен push у `main` збирає сайт і публікує його на Cloudflare (GitHub Actions)

## Запуск локально

```bash
npm install
```

```bash
npm run dev
```

- Сайт: http://localhost:4321
- Адмінка: http://localhost:4321/admin (пароль у `.dev.vars`, рядок `ADMIN_PASSWORD`)

Локально використовуються змінні з `.dev.vars` (приклад: `.dev.vars.example`). Якщо в них є `SUPABASE_URL` і `SUPABASE_SERVICE_ROLE_KEY`, локальний сайт працює з тією самою базою, що й продакшен, тож тестові заявки й зміни з адмінки потрапляють у реальні дані. Для окремої бази створіть другий проєкт Supabase.

Без Supabase сайт працює в демо-режимі: дані живуть у пам'яті процесу й зникають після перезапуску.

```bash
npm run check
```

Перевірка типів (`tsc`). `astro check` не використовується, бо не підтримує TypeScript 7.

## Сторінки

| Адреса | Що це |
| :--- | :--- |
| `/` | Головна з блоків: перший екран із гравюрою Tesla, марки, прайс, кроки, переваги, запис, питання, контакти |
| `/poslugy/` | Усі послуги картками |
| `/<slug>/` | Окрема сторінка кожної послуги, напр. `/planove-to/`, з формою запису |
| `/tsiny/` | Повний прайс |
| `/zapchastyny/` | Запчастини картками за категоріями |
| `/kontakty/` | Контакти, карта, маршрут |
| `/admin` | Адмінка |
| `/sitemap.xml`, `/robots.txt`, 404 | Службові |

Сторінки рендеряться на Worker при кожному запиті, тому зміни з адмінки видно на сайті одразу.

## Що редагується в адмінці

- **Заявки**: записи з форми з датою створення, статус (нова, підтверджена, виконана, скасована). Скасування звільняє слот.
- **Розклад**: типовий тиждень (час візитів по днях) і винятки на конкретний день: закрити слот, додати час, зробити вихідний.
- **Послуги і ціни**: назва, адреса сторінки, ціна «від», тривалість, опис, перелік робіт, SEO. Ціну можна міняти прямо в списку.
- **Запчастини**: назва, категорія, опис, ціна, наявність.
- **Головна сторінка**: порядок блоків, показати або сховати, усі тексти. Можна додати текстовий блок, банер, відгуки. У блоці «Перший екран» редагуються вузли гравюри Tesla.
- **Налаштування**: назва, телефон, адреса, координати, графік, месенджери, адреса сайту, SEO головної.

## Перший екран: гравюра Tesla

На правій частині першого екрана гравюра Tesla (вид зверху) з анімованою підсвіткою шести частин: батарея, ходова, електроніка, скло, зарядка, тепловий насос. Кожен вузол показує ціну «від» і веде на сторінку послуги.

Гравюру створює скрипт з фото `img/tesla-top-source.jpg`. Вихідне фото в репозиторій не входить. Щоб замінити фото:

```bash
node scripts/engrave.mjs шлях/до/фото.jpg
```

Скрипт повертає фото на 90°, лишає контури, передає тони штрихуванням і зберігає `public/img/tesla-engraving.webp` та шар скла `tesla-glass.webp`. Припускається, що авто знято зверху, носом угору, на білому тлі.

Вузли (назва, текст, адреса послуги, частина авто) редагуються в адмінці. Частина авто задається словом: `battery`, `chassis`, `electronics`, `glass`, `charge`, `climate`. Розташування підсвіток на гравюрі задане в `src/components/blocks/Hero.astro`.

## Форма запису

- Клієнт обирає день і вільний слот, які виставляє адмін. Після заявки слот стає зайнятим, повторний запис на той самий час відхиляється (унікальний індекс у базі).
- Поле телефону само підставляє `+380` і форматує номер. Приймає `066…`, `380…`, `+380…` і вставлення.
- VIN-код необов'язковий: 17 латинських літер і цифр без I, O, Q.
- Біля кнопки примітка про згоду на обробку персональних даних і дзвінок.
- Захист від ботів: приховане поле-пастка і Cloudflare Turnstile (вмикається змінними).
- Кожна заявка надходить у Telegram з датою й часом створення за Києвом.

## Як влаштовано

- `src/lib/seed.ts` — початкові дані з макета, вузли гравюри за замовчуванням.
- `src/lib/store.ts` — доступ до даних: Supabase або демо-сховище в пам'яті.
- `src/lib/schedule.ts` — розрахунок вільних слотів (час за Києвом).
- `src/lib/site.ts` — спільні дані сторінок, карта, розмітка schema.org.
- `src/lib/auth.ts` — вхід в адмінку: пароль із секрету, підписана cookie.
- `src/styles/site.css` — стилі макета без змін; `extra.css` — стилі нових сторінок і гравюри; `admin.css` — Tailwind для адмінки.
- `src/components/admin/AdminApp.tsx` — адмінка (React + Tailwind).
- `src/components/BookingForm.tsx` — форма запису (React).
- `src/pages/api/` — слоти, запис, адмінка.
- `supabase/schema.sql` — схема бази.
- `scripts/engrave.mjs` — генерація гравюри.
- `.github/workflows/` — CI і деплой.

## Змінні середовища

Локально вони лежать у `.dev.vars`, на Cloudflare це секрети Worker. Перелік і коментарі: `.dev.vars.example`.

| Змінна | Призначення |
| :--- | :--- |
| `ADMIN_PASSWORD` | Пароль входу в `/admin` |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | База даних; ключ використовується тільки на сервері |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Сповіщення про заявки |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | Перевірка форми від ботів (необов'язково) |

Файли `.dev.vars` і `.prod.vars` у `.gitignore` і в репозиторій не потрапляють. Змінити секрет на Cloudflare:

```bash
npx wrangler secret put ADMIN_PASSWORD
```

## База даних (Supabase)

Схема в `supabase/schema.sql`: таблиці `site_content`, `services`, `parts`, `bookings`, RLS увімкнено й публічних політик немає, тож з anon-ключем дані прочитати не можна. Доступ іде тільки через Worker із service role ключем.

Для нового проєкту виконайте схему в SQL Editor, додайте ключі й зайдіть в адмінку: початкові послуги, запчастини й тексти перенесуться в базу самі.

## Деплой

Автоматично: push у `main` запускає `.github/workflows/deploy.yml`, який збирає сайт і виконує `wrangler deploy`. Потрібні секрети репозиторію `CLOUDFLARE_API_TOKEN` (шаблон «Edit Cloudflare Workers») і `CLOUDFLARE_ACCOUNT_ID`. `ci.yml` на кожен push і PR перевіряє типи й збірку.

Вручну:

```bash
npx wrangler login
```

```bash
npm run deploy
```

Секрети самого Worker (таблиця вище) задаються окремо командою `wrangler secret put` і деплоєм не перезаписуються.

## Домен

Після підключення домену до Worker впишіть його в адмінці: Налаштування → Адреса сайту. Від цього залежать canonical, sitemap і розмітка.
